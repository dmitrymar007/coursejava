Задание 15. Полная граница ошибок CourseHub

Четыре вида ошибок

1. Валидация домена. Данные нарушают правила: id не положительный, пустое название, длительность вне 1..300, мест меньше 1. Это ValidationException, она бросается в конструкторе Course.
2. Ожидаемые отказы. Зачисление отклонено штатно: курс не найден, не открыт, повторная заявка, нет prerequisite, нет мест. Это значения EnrollmentResult, а не исключения. Битая запись при импорте это CourseHubException с кодом INVALID_RECORD и номером записи.
3. Инфраструктурная ошибка. Reader не читается или не закрывается. Это CourseHubException с кодом IMPORT_IO_ERROR. Исходный IOException сохраняется как cause, а ошибка закрытия при основной ошибке попадает в suppressed.
4. Ошибка программиста. null вместо обязательного аргумента. Это NullPointerException. Её никто не ловит и не превращает в код ошибки.

Что ловится на каждом уровне и почему

Домен (Course). Ничего не ловит. Бросает ValidationException для плохих данных и NullPointerException для null.

Прикладной слой (CourseHubService). Ловит только ValidationException, NumberFormatException и IOException и превращает их в CourseHubException с кодом, номером записи и cause. RuntimeException не ловит: это баг в коде, а не проблема данных, и подмена его кодом ошибки скрыла бы баг. Ресурс закрывается через try-with-resources. Курсы регистрируются только после успешного чтения и закрытия, поэтому частичного результата нет.

Публичный слой (CourseHubApi). Ловит только CourseHubException и превращает её в ApiResponse со стабильным кодом из ErrorCode. Клиенту отдаётся публичное сообщение без cause и деталей реализации. Ошибки программиста проходят через этот слой без изменений и доходят до внешней границы процесса (обработчик потока или сервера), где их логируют и отвечают общей внутренней ошибкой. Этот внешний обработчик в проекте не реализован.

Почему глобальный catch (Exception) запрещён

1. Он смешивает разные виды ошибок: битую запись пользователя и NullPointerException из-за бага он обработал бы одинаково.
2. Он скрывает баги: ошибка программиста превратилась бы в обычный отказ, и её никто бы не заметил.
3. Он теряет контекст: обработчик не знает, что произошло, и не может выбрать действие.
4. Он снимает защиту компилятора: конкретные проверяемые исключения заставляют явно решить, что делать на каждом уровне.

Тесты (23 прогона, все проходят в случайном порядке)

- CourseTest (5): четыре нарушения валидации с именем поля (параметризованный тест) и null как ошибка программиста.
- CourseEnrollTest (5): таблица решений зачисления, по строке на правило (параметризованный тест).
- CourseHubServiceTest (8): успешный импорт с закрытием reader, три варианта битой записи (параметризованный тест) с номером записи, cause и отсутствием частичного результата, ошибка чтения, ошибка только закрытия, битая запись вместе с ошибкой закрытия (suppressed), неизвестный курс.
- CourseHubApiTest (5): успех, код битой записи с номером, код ошибки ввода-вывода без внутренних деталей, код неизвестного курса, ошибка программиста не превращается в код.

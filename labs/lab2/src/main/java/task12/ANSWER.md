Хрупкий тест падает не из-за ошибки в коде, а из-за обстоятельств запуска. Были исправлены три причины.

1. Порядок выполнения и общий static state.
Было: реестр курсов хранил данные в статическом списке, общем для всех тестов. Тест a добавлял курс, тест b ожидал пустой реестр. Если b шёл после a, он падал (ожидалось 0, получено 1), а отдельно проходил.
Стало: данные хранятся в экземпляре CourseRegistry, и каждый тест создаёт новый реестр в методе с @BeforeEach. Общего состояния нет, порядок не важен.

2. Текущая директория.
Было: тест читал файл по относительному пути data/courses.txt и работал только при запуске из нужной директории.
Стало: тест сам создаёт файл во временной папке (@TempDir). Место запуска не важно, файлов в проекте не остаётся.

3. Точный текст toString.
Было: assertEquals сравнивал весь текст toString с эталонной строкой. Тест ломался при любой смене формата.
Стало: тест проверяет только то, что в тексте есть название и id курса.

Независимость тестов обеспечивают три вещи:
- файл junit-platform.properties включает случайный порядок классов и методов;
- в pom.xml у Surefire указан runOrder=random, seed печатается в лог для повторения прогона;
- каждый тест запускается отдельно командой mvn test -pl task12 -Dtest=Класс#метод.

Исправленные тесты (9 штук) проходят в случайном порядке, по отдельности и при запуске из корня lab2.

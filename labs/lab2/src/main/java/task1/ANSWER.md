Задание 1. Прочитать stack trace

В Demo метод method4 явно бросает RuntimeException с сообщением «Вызов исключения». Первая строка stack trace показывает тип и сообщение, первый кадр — место возникновения: Demo.method4. Далее идут вызвавшие его method3, method2, method1 и main.

Цепочка вызовов читается от main к method4, а stack trace печатается от места ошибки обратно к вызывающим методам. Последняя строка с main показывает вход в цепочку, а не причину сбоя.

В текущем примере причина — сам демонстрационный throw в method4. catch в main только печатает ошибку, после чего выводится «в работе...». Перехват не исправляет причину: для исправления нужно менять действие, которое породило исключение. Здесь оно намеренно оставлено для демонстрации.

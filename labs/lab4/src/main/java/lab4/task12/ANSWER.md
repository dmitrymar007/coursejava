В Europe/Berlin 31.03.2024 02:30 не существует: часы переводятся вперёд. Обычный `atZone` сдвигает это время к 03:30. Для занятия принято явное правило: gap отклоняем через `InvalidLocalTimeException`, чтобы организатор выбрал существующее время.

27.10.2024 02:30 встречается дважды. Выбираем первое вхождение с +02 (00:30Z); через час будет снова 02:30, но уже +01 (01:30Z). `getValidOffsets` позволяет отличить gap, обычное время и overlap; `ofStrict` фиксирует выбранный offset.

`plusHours(1)` двигается по временной шкале на 3600 секунд. `plusDays(1)` сохраняет календарное время по правилам зоны: от 30.03 12:00 до 31.03 12:00 проходит 23 часа. Такое календарное добавление само использует стандартное разрешение gap; при построении занятий каждую дату отдельно пропускаем через наш строгий resolver.

Формат `dd.MM.uuuu` с `ResolverStyle.STRICT` принимает 29.02.2024 и отклоняет 29.02.2023, 31.04.2024, неверную ширину полей, пробелы и хвост текста. `uuuu` — календарный год; `yyyy` — год эры, который в строгом режиме без эры может не разрешиться в LocalDate.

`InvalidDateFieldException` добавляет имя поля и исходное значение, сохраняя `DateTimeParseException` как cause. Для null исходного исключения парсера нет, поэтому cause отсутствует; значение и поле всё равно включены в сообщение. Общий catch Exception не используется.

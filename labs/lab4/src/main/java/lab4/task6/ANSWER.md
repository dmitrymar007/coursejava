Скидка распределяется пропорционально весам (например, ценам позиций). Каждая доля округляется до заданного scale с явно переданным `RoundingMode`. Разница с исходной суммой распределяется по одной минимальной единице слева направо; нулевые веса пропускаются, отрицательные доли не создаются. Это детерминированная политика, зависящая от порядка позиций.

Пример: 1.00 на три равных веса при DOWN → `[0.34, 0.33, 0.33]`. При округлении вверх лишние копейки таким же образом вычитаются. Для цен `[19.90, 29.95, 10.15]` скидка 5.00 с HALF_UP → `[1.65, 2.50, 0.85]`, сумма ровно 5.00.

Сумма должна уже иметь заданную точность; отрицательные веса/суммы и положительная сумма при нулевых весах отклоняются. UNNECESSARY сохраняет свой смысл: неразделимые без округления доли вызывают исключение. Общий алгоритм используется также в Money, где scale определяется валютой.

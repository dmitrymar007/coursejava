Задание 6. Масштаб и округление

DiscountAllocator распределяет скидку пропорционально весам, например ценам позиций. Количество знаков после запятой и RoundingMode передаются явно. Сначала вычисляется и округляется каждая доля, затем их сумма сравнивается с исходной скидкой.

Остаток распределяется по одной минимальной денежной единице слева направо. Если после округления сумма стала больше нужной, лишние копейки вычитаются в том же порядке. Нулевые веса пропускаются, отрицательные доли не создаются. При одинаковых входных данных результат всегда одинаков.

При распределении 1.00 на три равных веса с DOWN получаем 0.34, 0.33 и 0.33. Для цен 19.90, 29.95 и 10.15 скидка 5.00 с HALF_UP распределяется как 1.65, 2.50 и 0.85. В обоих случаях сумма долей точно равна исходной сумме.

Исходная сумма должна соответствовать заданной точности. Отрицательные суммы и веса запрещены, положительную сумму нельзя распределить по полностью нулевым весам. При UNNECESSARY дробные доли, требующие округления, вызывают исключение. Этот же алгоритм используется в Money.

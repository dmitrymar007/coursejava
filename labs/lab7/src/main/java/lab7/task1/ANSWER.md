Задание 1. Потерянные инкременты

counter++ состоит из чтения значения, вычисления value + 1 и записи. Два потока могут прочитать 0, вычислить 1 и оба записать 1: вместо 2 получится 1. UnsafeCounter показывает обычный ++ и его разложение. Барьер между вычислением и записью воспроизводит конкретное ошибочное чередование, а не надеется на планировщик. После Future.get результаты доступны вызывающему потоку.

Инвариант исправленных счётчиков: значение равно числу завершённых инкрементов; каждое увеличение выполняется целиком под одним монитором. У MethodCounter монитор — this, у BlockCounter — приватный lock. Чтение также защищено тем же монитором. Метод synchronized блокирует весь метод; минимальный блок позволяет оставить несвязанную работу снаружи. Здесь метод короткий, поэтому существенной разницы в объёме защищённого кода нет. Приватный монитор не доступен внешнему коду.

CountersTest проверяет оба исправления на 40 000 увеличений. Тест задания 5 тридцать раз выявляет потерю инкремента в ошибочном варианте.

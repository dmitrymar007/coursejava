Задание 5. Детерминированный конкурентный тест

DeterministicRaceTest использует сценарий Counters.lostIncrement из задания 1. CyclicBarrier(2) не выпускает потоки к записи, пока оба не прочитают старое значение и не вычислят следующее. Оба записывают 1. Future.get ожидает завершения обеих записей, затем тест проверяет 1 вместо ожидаемых 2. Так ошибка воспроизводится тридцать раз без зависимости от случайного переключения потоков.

Thread.sleep не используется. Есть JUnit @Timeout(15), ограниченные ожидания барьера и Future, executor всегда освобождается в finally. Если один участник не добрался до барьера, второй выйдет по timeout, а не зависнет навсегда. main повторяет тот же опыт пять раз. Исправленные счётчики проверяются отдельно в задании 1; барьер внутри synchronized привёл бы к взаимному ожиданию.

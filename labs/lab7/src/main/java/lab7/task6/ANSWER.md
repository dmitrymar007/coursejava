Задание 6. Запись на курс с ограничением мест

Контракт: enroll возвращает true только при новой успешной записи. Вместимость неотрицательна, студент задаётся непустой ссылкой String. Уже записанный студент и переполненный курс получают false без изменения состояния. Набор студентов одновременно задаёт количество занятых мест и исключает дубликаты; отдельный счётчик не нужен.

LockedCourse защищает проверки и добавление одним synchronized-методом, монитор — this. Это coarse-grained lock: операции одного курса выполняются последовательно. Снимок участников создаётся под тем же монитором. Решение простое, без повторных попыток и копирования при записи.

AtomicCourse хранит неизменяемый Set в AtomicReference. Проверяет текущий снимок, строит новый и публикует compareAndSet. Если другой поток успел изменить состояние, повторяет проверку на новом снимке. Точка успешной записи — CAS. Неудачная попытка CAS не публикует промежуточное состояние. Читатели получают готовый неизменяемый снимок без блокировки. Цена — копирование O(n) при попытке записи и возможные повторы при конкуренции; индивидуальный поток может долго проигрывать CAS.

ConcurrentHashMap.newKeySet() атомарно исключает дубликаты, но связка size() < capacity и add() не атомарна: разные студенты могут одновременно занять последнее место. Отдельный AtomicInteger также не связывает проверку лимита с уникальностью студента. Нужен общий протокол: блокировка составной операции либо CAS всего состояния. Поэтому здесь реализованы именно эти два варианта.

Тесты для обоих вариантов запускают 200 заявок из 8 потоков при capacity=10, с повторяющимися студентами. Проверяются ровно 10 успехов, отсутствие лишних участников, неизменность при отказе, повторная запись при свободных местах, нулевая/отрицательная вместимость, null и неизменяемость снимка.

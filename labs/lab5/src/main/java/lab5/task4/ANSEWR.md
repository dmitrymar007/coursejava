Задание 4. Ленивые строки

count открывает Files.lines внутри try-with-resources и выполняет терминальную операцию до закрытия. Сам по себе count не закрывает stream; это делает try. Ошибки чтения при ленивом обходе могут приходить как UncheckedIOException.

brokenLines намеренно возвращает stream из try: при выходе он уже закрыт, поэтому count снаружи бросает IllegalStateException. Это воспроизводится в main и тесте. Владелец ресурса обязан закрыть его после потребления; здесь владение остаётся внутри метода, поэтому наружу нужно возвращать готовый результат, как в count.

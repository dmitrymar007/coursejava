Задание 6. Собственный collector

collector создаёт отдельный Accumulator через supplier. add обновляет count, sum, min и max. merge складывает count и sum и объединяет границы через min/max; это те же операции над непересекающимися частями входа, поэтому combiner корректен и ассоциативен в пределах диапазона long. Изменяемого static state нет.

finisher возвращает record Stats с примитивными полями: изменить опубликованный результат нельзя. Объявлена только характеристика UNORDERED, потому что порядок не влияет на статистику. CONCURRENT не подходит: один Accumulator не предназначен для конкурентного изменения. IDENTITY_FINISH не подходит: тип результата отличается от типа накопителя.

Для пустого потока count = sum = 0, min = Integer.MAX_VALUE, max = Integer.MIN_VALUE, как у summarizingInt. Эти границы при count = 0 не являются наблюдениями. sum имеет тип long; как и стандартный collector, при переполнении long арифметика переполняется. Обычный summarizingInt короче и предпочтительнее в рабочем коде; собственный здесь демонстрирует устройство collector.

Время O(n), дополнительная память последовательного накопления O(1). Тест сравнивает 10 000 значений со стандартной статистикой и parallelStream. Отдельно проверяются ручное объединение двух частей, пустой накопитель с обеих сторон, повторный сбор без утечки состояния, пустой поток и одиночный ноль.

Нарушение симметричности: equals у Point проверяет instanceof Point, а у ColoredPoint требует ещё и совпадение цвета. Поэтому Point(1, 2).equals(ColoredPoint(1, 2, red)) даёт true, а в обратную сторону false. От порядка вызова зависит результат, например contains в списке.

Исправление 1, строгое равенство: сравнивать getClass() вместо instanceof. Симметричность появляется, но нарушается LSP: объект анонимного подкласса Point уже не равен обычному Point, хотя ведёт себя так же.

Исправление 2, композиция: ColoredPoint не наследует Point, а содержит его как поле (оба типа record). Это разные типы, они не равны друг другу в обе стороны, и симметричность сохраняется без оговорок.

Final value class проще, потому что контракт equals нельзя выполнить полностью, если у расширяемого класса есть подкласс с новым полем: приходится жертвовать симметричностью или LSP. У final класса подклассов нет, поэтому хватает одной проверки типа, а equals и hashCode остаются согласованными. Если нужна точка с цветом, лучше использовать композицию.

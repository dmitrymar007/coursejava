В LegacyNotificationService поведение выбирается через switch по строке notificationType. Каждый новый тип это правка switch, а опечатка в строке видна только во время выполнения.

Теперь различия вынесены в интерфейс NotificationChannel с реализациями EmailChannel, SmsChannel и PushChannel. ChannelRegistry один раз сопоставляет строку конфигурации и объект, а NotificationService просто вызывает нужный канал и не знает конкретных классов.

Граница оправданного полиморфизма такая: отдельный класс нужен, когда различается алгоритм (формат сообщения, правила обрезки). Если различаются только данные, например адрес отправителя или лимит длины, это параметры конструктора, а не новый класс. Поэтому email и email-support это два объекта одного EmailChannel с разным from, а лимит SMS передаётся в SmsChannel. Создавать класс на каждую строку конфигурации не нужно. Проверка простая: меняется код метода или только значения.

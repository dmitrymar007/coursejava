Задание 9. Политика допуска как стратегия

EnrollmentPolicy возвращает Optional<String>: пустое значение означает допуск, строка — причину отказа. AgePolicy проверяет возраст, PrerequisitePolicy — пройденные курсы, CapacityPolicy — наличие мест.

EnrollmentService получает список политик и Enrollments через конструктор. При зачислении он вызывает каждую политику через интерфейс, собирает все нарушения и добавляет студента только при пустом списке ошибок.

Новая NoDuplicatePolicy и лямбда проверки имени добавляются при сборке списка в Main. EnrollmentService менять не нужно: ему важен контракт политики, а не конкретный класс. Это композиция стратегий, поэтому набор проверок можно менять независимо от сервиса.

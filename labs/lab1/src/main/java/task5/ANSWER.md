Задание 5. Интерфейс или абстрактный класс

Identifiable - интерфейс. Это просто способность иметь id, состояния нет, и интерфейс можно добавить любому классу. Цена изменения: если добавить в него новый абстрактный метод, сломаются все реализации.

CoursePolicy - интерфейс с одним методом, поэтому его удобно писать лямбдой. Новые политики добавляются бесплатно, но второй абстрактный метод сломал бы все лямбды.

BaseEntity - абстрактный класс. Нужны общее поле экземпляра id и final-реализации equals и hashCode. Интерфейс не хранит состояние экземпляра и не может дать default-реализации методов Object. Цена изменения высокая: единственное место для наследования занято, и правка equals затронет все подклассы BaseEntity. Здесь равенство определяется классом и id.

Formatter - интерфейс с одним методом, обобщённый, подходит для любого типа. Состояния нет, наследовать нечего. Цена изменения низкая, новые методы можно добавить через default.

ClockProvider - отдельный тип не нужен. В java.time уже есть Clock, и в тестах его можно подменить через Clock.fixed. Своя обёртка ничего бы не добавила. Если потом понадобится что-то сверх времени, тип введём тогда, и придётся заменить Clock в конструкторах.

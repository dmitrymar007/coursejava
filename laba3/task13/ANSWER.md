Задание 13. Обратный индекс

Индекс это Map<Tag, Set<CourseId>>.

HashMap<Tag, Set<CourseId>> для тегов: поиск по тегу за O(1), порядок тегов для работы индекса не нужен. Tag это record, поэтому equals и hashCode правильные, а ключ неизменяем.
HashSet для курсов: добавление, удаление и проверка за O(1), а Set сам не допускает повтора курса в теге.
HashMap<CourseId, Set<Tag>> обратная карта: какие теги у курса записаны в индексе. По ней remove(CourseId) снимает курс ровно с тех тегов, под которыми он был добавлен, даже если вызывающий код уже изменил свой объект. Без неё в индексе оставались бы устаревшие записи.
Set<Tag> в Course копируется через Set.copyOf при создании, поэтому набор тегов нельзя изменить снаружи после add.

Добавление курса: computeIfAbsent создаёт множество при первом курсе с тегом. Повторный add того же id сначала снимает старые теги, то есть заменяет курс целиком.
Удаление курса: по обратной карте убираем id из множества каждого его тега, и если множество стало пустым, удаляем тег из индекса. Поэтому пустых set в индексе нет. Удаление неизвестного id возвращает false.
Пересечение тегов: берём копию множества первого тега и вызываем retainAll для остальных, копия нужна, чтобы не испортить множества внутри индекса. Неизвестный тег, пустой набор тегов или пустое пересечение дают пустое множество сразу. Результат всегда неизменяемый.
tags() возвращает неизменяемую копию на LinkedHashSet: порядок обхода стабилен между запусками (Set.copyOf перемешивает порядок при каждом запуске JVM).

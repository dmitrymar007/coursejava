Задание 11. Выбор по нагрузке

1. Каталог по ID: Map, реализация HashMap. get, put, remove за O(1). 
Порядок не гарантирован. Память минимальная.

2. Отсортированный leaderboard: NavigableMap или TreeSet, реализация TreeMap/TreeSet.
 Вставка, удаление, первый и последний элемент за O(log n). Порядок задаёт компаратор, 
 он должен различать разные записи (нужен tie-breaker). Дерево тяжелее хеш-таблицы по памяти.

3. Очередь: Queue/Deque, реализация ArrayDeque. offer, poll, peek за O(1). 
Нужен приоритет: PriorityQueue (O(log n)).

4. Уникальные теги с порядком: Set, реализация LinkedHashSet (порядок появления, O(1)). 
Если нужен алфавитный порядок, то TreeSet (O(log n)). Порядок стоит дополнительной памяти.

5. Диапазонный поиск: NavigableMap, реализация TreeMap. subMap, headMap, tailMap за O(log n)
 на поиск границы плюс O(k) на выдачу k элементов. HashMap диапазоны не умеет, 
 пришлось бы перебирать всё за O(n).

6. Частый доступ по индексу: List, реализация ArrayList. get и set за O(1), 
добавление в конец амортизированно O(1), вставка в середину O(n). 
Память компактная, один массив.

Общий принцип: сначала решаем, какая операция нужна (по ключу, порядок, очередь, 
диапазон, индекс), потом выбираем интерфейс и только после этого реализацию. 
Чем строже порядок, тем дороже: HashMap O(1) без порядка, 
LinkedHashMap с порядком вставки за память, TreeMap с сортировкой за O(log n).
